# BTC 개인 자동매매 · 모의매매 MVP

업비트 `KRW-BTC` 공개 시세를 받아 이동평균 교차 전략을 실행하는 개인용 모의매매 시스템입니다.
**실제 주문 기능은 포함하지 않으며 API 키가 필요하지 않습니다.**

## 실행

Python 3.9 이상, macOS 또는 Linux 환경에서 실행합니다.

**macOS:** 프로젝트 폴더의 `서버시작.command`를 더블클릭하면 서버가 백그라운드에서 시작되고
관리 화면이 열립니다. `서버중지.command`를 더블클릭하면 시세 수집까지 종료합니다.
터미널 창을 닫아도 서버는 계속 실행됩니다. 컴퓨터 재부팅 후 자동 시작은 하지 않습니다.

**터미널:** 프로젝트 폴더에서 다음 명령을 사용합니다.

```sh
./server start          # 백그라운드 시작
./server start --open   # 시작하고 관리 화면 열기
./server stop           # 정상 종료
./server restart        # 재시작 (자동매매는 정지 상태)
./server status         # 실행 상태 확인
./server logs           # 최근 서버 로그 확인
```

첫 시작에 `.venv`와 필수 패키지를 자동으로 준비합니다. 이미 실행 중이면 중복 실행하지 않습니다.
서버를 중지해도 가상 잔고와 거래 기록은 보존합니다. 실행 정보와 로그는 `.run/`에 저장합니다.
로그는 자동 순환하지 않으므로 장기 운영 시 서버를 중지한 뒤 `.run/server.log`를 정리할 수 있습니다.
이 실행기로 시작한 프로세스만 종료하며, 다른 프로그램이 8000 포트를 쓰면 충돌을 안내합니다.
기존에 직접 실행한 Uvicorn은 해당 터미널에서 `Ctrl+C`로 종료한 뒤 실행기를 사용하세요.

직접 실행하려면:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
uvicorn trade.app:create_app --factory --host 127.0.0.1 --port 8000 --workers 1
```

[관리 화면](http://127.0.0.1:8000)을 열고 시세 수신을 확인한 뒤 **거래 시작**을 누릅니다.
기본 가상 예산은 100만원입니다. 기본 전략은 확정된 1시간봉 MA 5/20 교차로, 신호가 없으면 거래하지 않습니다.
화면은 5초마다 갱신하고 시세는 30초마다 수집합니다.

- **거래 시작:** 새로운 전략 판단과 모의 체결을 처리합니다.
- **거래 정지:** 모든 전략 거래를 중지하고 시세 수집은 유지합니다. 보유 BTC를 매도하지 않습니다.
- **신규 매수 중지:** 매수만 차단하고 매도 신호는 계속 처리합니다.
- **신규 매수 재개:** 최신 시세와 일일 손실 한도 검사 후 매수 차단을 해제합니다.

서버 재시작 후에는 항상 거래 정지 상태입니다. 자금·체결·매수 중지 상태는 보존합니다.
시세 오류가 발생해도 거래를 정지하며, 수신 복구 후 시작 버튼으로 재개해야 합니다.

## 기본 운영 규칙

| 항목 | 기본값 |
|---|---|
| 가상 초기 원화 | 1,000,000원 |
| 1회 매수 금액 | 최대 100,000원 + 수수료 |
| 최대 BTC 보유 비중 | 평가 자산의 30% |
| 일일 손실 한도 | 기준 자산 대비 3% 하락 시 신규 매수 차단 |
| 가정 편도 수수료 | 0.05% |
| 가정 편도 슬리피지 | 0.1% |
| 최소 모의 주문 금액 | 5,000원 |

수수료·슬리피지·최소 금액은 시뮬레이터의 가정입니다. 실제 계정 조건을 조회한 값이 아닙니다.
매수 금액은 현금·보유 비중 한도에 따라 줄어들 수 있고, 매도 신호에서는 가상 BTC 전량을 매도합니다.
원화는 Decimal, BTC 수량은 8자리 내림으로 계산합니다. 수수료는 매수 원가에 포함하고 매도 수익에서 차감합니다.

캔들 확정 후 2분 이내의 교차만 사용합니다. 진행 중인 캔들, 누락 구간, 과거 신호의 재실행은 배제합니다.
모의 체결가는 판단 시점 이후 수신한 현재가에 슬리피지를 적용합니다. 확정 캔들 종가에 소급 체결하지 않습니다.
같은 캔들의 판단·체결·잔고 변경은 SQLite 트랜잭션 하나로 기록해 재시작과 중복 수신에 대응합니다.

일일 손실 기준은 한국시간 날짜별 **첫 정상 시세 관측 시점의 평가 자산**입니다.
자정에 수집이 중단되어 있었다면 정확한 자정 자산과 다를 수 있습니다.
매수 차단은 날짜가 바뀌어도 유지하며, 수동으로 재개합니다. 자동 손절·자동 청산 기능은 없습니다.

## 설정

`.env.example`에 지원하는 환경변수가 있습니다. `.env` 자동 로드는 하지 않습니다.

```sh
export TRADE_INITIAL_CASH=2000000
export TRADE_ORDER_KRW=100000
export TRADE_DB_PATH=data/scenario-2.sqlite3
./server start
```

기존 계좌의 예산·전략·위험 설정을 바꾸면 시작을 거부합니다. 다른 설정을 시험하려면 새 DB 경로를 지정하세요.
`data/trade.sqlite3`에 모든 상태를 보관합니다. 백업 시에는 서버를 종료한 후 DB를 복사하세요.
같은 DB의 동시 실행은 파일 잠금으로 방지합니다. Uvicorn은 단일 워커로 실행해야 합니다.
기본 주소는 로컬 전용이며, 인증 없는 관리 화면을 외부에 노출하지 마세요.

Docker가 있으면 `docker compose up --build -d`로 실행할 수 있습니다.
호스트의 `127.0.0.1:8000`에 연결하며 데이터는 `trade-data` 볼륨에 보관합니다.
Docker 구성은 제공되지만 현재 개발 환경에 Docker가 없어 실행 검증하지 않았습니다.

## 검증

```sh
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
```

전략 교차, 미래 캔들 제외, 누락 캔들, 수수료·슬리피지 손익, 보유 비중,
중복 신호, 재시작, 트랜잭션 롤백, 한국시간 날짜 전환, 손실 한도,
API 제어와 동일 DB 중복 실행 방지를 검증합니다. 테스트는 네트워크와 실제 주문을 사용하지 않습니다.

## 구조와 다음 단계

```text
trade/config.py      환경변수 및 설정 검증
trade/market.py      업비트 공개 REST 시세 수집
trade/strategy.py    확정 캔들 이동평균 교차 판단
trade/engine.py      거래 상태·위험 관리·가상 체결
trade/storage.py     SQLite 저장소
trade/app.py         수집 루프·로컬 관리 API
trade/static/        한국어 대시보드
server              로컬 서버 시작·중지 명령
scripts/server.py   백그라운드 프로세스 관리
tests/              회계·위험·재시작·API 검증
```

이 버전은 실시간 모의매매의 첫 동작 버전입니다. 별도 백테스트 CLI, 장기 데이터 수집,
알림 채널, 실거래 주문·부분 체결·취소·계좌 동기화는 아직 구현하지 않았습니다.
초기 시세 로딩은 최대 200개 캔들이며 이후 관측한 캔들을 누적합니다.
가상 즉시 전량 체결을 가정하므로 실제 호가·대기열·부분 체결을 재현하지 않습니다.
전략 수익성을 검증한 결과는 아닙니다.
